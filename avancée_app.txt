  UX bien pensée

  - Reset visuel sans perdre les stats (intelligent)

  ⚠️ Problèmes réels

  1. Code dupliqué massif (script.js:1362-2013)
  - Les fonctions groupe sont définies 2x : dans script.js ET dans script_group.js
  - createGroup, showJoinForm, doCreateGroup, etc. existent en double
  - generateGroupCode apparaît 2 fois identique
  - Maintenance cauchemar : modifier un bug = le fixer à 2 endroits

  2. Système de groupe cassé
  - GitHub Gist API sans authentification → 401 systématique
  - Fallback localStorage seulement local → partage impossible
  - findGroupByCode() cherche dans localStorage, pas sur GitHub
  - Le créateur stocke le mapping localement, les autres ne peuvent pas le trouver
  - La fonctionnalité groupe ne peut PAS fonctionner en l'état

  3. Architecture de données fragile
  // script.js:748-751
  if (!counters[currentCategory][currentDate]) {
      counters[currentCategory][currentDate] = 0;
  }
  counters[currentCategory][currentDate]++;
  - Structure counters[category][dateString] = number
  - Script.js:1034 tente d'utiliser une structure différente (daily, weekly, monthly) dans resetAllData()
  - Incohérence qui causera un bug lors du reset total

  4. Variables globales partout
  let categories = ...
  let counters = ...
  let currentCategory = ''
  let visualOffset = 0
  let soundEnabled = ...
  let tickSound = null
  let isHost = false
  let connections = new Map()
  let currentGroup = null
  let participantName = null
  ...
  - 15+ variables globales
  - Aucune encapsulation
  - Collision de noms possible
  - Difficile à tester

  5. Gestion son chaotique
  - 3 implémentations : fichier MP3 + Web Audio + WAV généré (script.js:42-204)
  - Logique complexe pour mobile (enableAudioOnInteraction)
  - Code mort : createSimpleTickSound() défini mais jamais appelé
  - tesbih_variant_1.mp3 référencé mais absent du repo

  6. Pas de gestion d'erreur réseau
  // script_group.js:70
  const response = await fetch(GIST_API_URL, {
      method: 'POST',
      headers: {
          'Content-Type': 'application/json'
      },
      body: JSON.stringify(gistData)
  });
  - Pas de retry
  - Pas de timeout
  - Pas d'indication de connexion
  - L'utilisateur ne sait pas si ça marche

  7. Typo dans l'UI
  <!-- index.html:96 -->
  <p>📱 Uygulamaı kapattığınızda bile kalır</p>
  "Uygulamaı" → "Uygulamayı"

  8. CSS redondant
  - .custom-alert et .custom-confirm très similaires
  - Styles inline dans JavaScript (script.js:1007-1015)
  - Pas de CSS variables pour les couleurs répétées

  9. Logique métier éparpillée
  - Calcul des stats dans getStatisticsForCategory()
  - Mais aussi dans updateStats()
  - Et dans getCurrentUserStats()
  - 3 endroits pour faire la même chose

  10. Performance
  // script.js:1294-1296
  setInterval(autoSave, 30000);
  setInterval(updateSaveStatus, 60000);
  setInterval(updateStats, 60000);
  - 3 intervals qui tournent en permanence
  - updateStats() parcourt toutes les catégories × toutes les dates à chaque appel
  - Pas de debounce ni throttle
  - Batterie mobile qui souffre

  🔥 Le vrai problème : la fonctionnalité groupe

  Le système GitHub Gist était une mauvaise idée dès le départ :
  - Nécessite un token personnel (sécurité ❌)
  - Rate limit GitHub (60 req/h sans auth)
  - Pas de WebSocket → polling toutes les 10s
  - localStorage mapping ne sync pas entre users

  Solutions réalistes :
  1. Firebase Realtime Database (gratuit jusqu'à 10GB)
  2. Supabase (PostgreSQL + realtime)
  3. PeerJS/WebRTC direct (déjà dans le code mais pas utilisé)
  4. Backend simple (Cloudflare Workers + KV)
